# Project design context

This file records the creator-confirmed context that guides product and
interaction design for the inspiration library.

## Design Context

The product is a local-first reference and learning workspace. It helps a
designer-developer revisit saved work, inspect specific aspects of a source,
learn the correct domain language, and translate observations into practical
implementation knowledge.

### Users

The primary user is a learning designer-developer. They alternate between two
intentional modes: exploring saved design, project, and idea references, and
asking grounded questions about one or more saved sources. Their questions
include how an effect works, how to implement it, what a movement or technique
is called, and how to describe it accurately in domain language.

The user usually arrives curious and focused rather than hurried. They need to
move fluidly between visual inspection, comparison, terminology, and practical
recreation without losing the source context that prompted the question.

### Brand personality

The product is spatial, fluid, and exploratory. It treats sources, annotations,
questions, lessons, and vocabulary as parts of one evolving workspace rather
than isolated records or a generic chatbot history.

The interface must feel consequential without feeling heavy. Actions reveal
their effect, preserve context, and reward curiosity with useful feedback.

### Aesthetic direction

The experience resembles a navigable field of references and ideas. Context
must remain perceptible as the user moves from a library source into a focused
inspection, a multi-source question, or a saved lesson. Transitions must express
continuity and state change, not add decoration.

Onboarding is the user's first act of authorship. Identity, learning context,
tool preferences, and the first saved source must transform a real workspace
preview as the user makes each choice. Onboarding must not resemble account
paperwork or collect answers without visible consequence. The exact visual
theme, typography, color system, and layout remain intentionally unresolved
until the interaction brief is confirmed.

### Design principles

These principles guide every major screen and journey:

- **Keep the source visible in the learning loop.** Questions, terminology, and
  implementation guidance must remain anchored to inspectable evidence.
- **Make authorship visible.** A preference, source, note, collection, or saved
  term must immediately change the user's real workspace or learning context.
- **Preserve spatial continuity.** Moving among library, source, comparison,
  lesson, and vocabulary contexts must not feel like switching products.
- **Progressively disclose intelligence.** The local library works first. AI
  connection appears at the moment the user asks for model-assisted analysis.
- **Separate fact from suggestion.** Distinguish captured evidence,
  user-authored content, glossary-backed language, and model-generated
  candidates.
- **Keep recovery understandable.** Durable save, background enrichment,
  provider availability, and recoverable failure must remain distinct states.
